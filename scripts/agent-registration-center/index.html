                Agent token 如何获取？为什么 Nacos 登录后还需要它？
              
              

                

                  本仓库 Agent 的 A2A 默认允许匿名访问，可留空 token。
                  只有部署者设置
                  DESIGN_AGENT_A2A_ALLOW_ANONYMOUS=false
                  后才需要下面的凭证；请以当前 AgentCard 声明为准。
                

                

                  向目标 Agent 的部署者 / 管理员申请调用凭证。这是目标服务的访问权限，不是 Nacos 密码或
                  accessToken，也不是模型供应商 API key。AgentCard
                  只描述鉴权方式，不包含真实 token。
                

                
    
                  
  1. 
                    确认当前选中的 Agent
                    和调用端点，向该服务的部署者申请与你的调用身份对应的 token。
                  
    2. 
                  
  2. 
                    如果目标是本仓库的 Agent：由服务器管理员查看该 Agent
                    启动时加载的
                    DESIGN_AGENT_ACCESS_TOKEN_CALLERS。配置格式为
                    <token>:<caller-id>,...，这里只填写
                    token 部分，不带 caller-id 或 Bearer  前缀。
                  
    3. 
                  
  3. 
                    其它 harness 的 token 由其服务或鉴权网关配置 /
                    签发，按部署者提供的方法获取；不能从 Nacos
                    目录中推算或自动领取。
                  
    4. 
                  
  4. 
                    本应用可用
                    --credentials-file /path/to/private-access.json
                    或环境变量
                    ARC_CREDENTIALS_FILE 加载受保护文件的
                    origin/token。重启应用后勾选“使用本地 Agent
                    凭证”；不会把文件中的 token 返回到页面。
                  
    5. 
                

                

                  缺少 token：本地提示，任务未提交。HTTP
                  401：目标服务未接受凭证，请确认 token 是否正确、有效且属于当前
                  Agent。HTTP 403：目标服务拒绝访问，需部署者检查账号 /
                  任务权限。
